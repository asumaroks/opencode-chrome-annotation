## Контракт установленного OpenChamber

Проверяемая версия 2.5.2. В assets/useAppFontEffects-DFJQ0O1i.js найден компонент _vt штатного меню mention, уже обслуживающий клавиатуру через imperative handle. Адаптер должен добавлять строки в этот компонент и общий подсчёт/выбор, а не перехватывать DOM-клавиатуру. Composer предоставляет P.current.getSelection/getValue/setSelection, m/h (текст/setter), E (закрытие), nt (runtimeKey/directory/sessionId), eo (directory/sessionKey) и $r (штатный inline context store). Патч допускается только по проверенным уникальным маркерам и SHA256 исходной сборки.

## Принятые решения реализации

- Origin расширения: принимается любой корректный `chrome-extension://<32 символа a-p>`, потому что id распакованного расширения не существует до установки. Согласием считается сопряжение одноразовым 8-значным кодом; adapter-origins при этом никогда не доверяются неявно и берутся только из allowlist.
- Тесты адаптера не вендорят куски минифицированного бандла: фикстуры синтетические (маркеры манифеста по одному на патч), а реальный asset проверяется отдельно и только при заданном `OPENCHAMBER_ASSET_PATH`.
- Установщик: dry-run по умолчанию, запись только с `-Apply`, откат через `-Rollback` по `.octm-install.json` и резервной копии. `-ExpectedSha256` предназначен только для тестовых фикстур, печатает `OVERRIDE` и не заменяет пин сборки.

## Что осталось непроверенным

- Реальный диалог разрешения Chrome на доступ к сайту: показан ли он и как выглядит для пользователя.
- Живой цикл сопряжения extension ↔ adapter в запущенном приложении: код, поллинг, истечение и повторное сопряжение.
- Фактическая отрисовка @-меню (порядок строк, подсветка), поведение мыши и IME при выборе вкладки.
- Сериализация Send через настоящий composer: порядок attachment и текста, поведение при отмене и удалении.
- Не проверено, что уже установленная машина продолжает работать до перезапуска лаунчера: приложение и его service-worker могут продолжать отдавать прежний или уже подменённый ассет.

## Решения и риски

Установленные assets и plugin config изменять только после резервной копии. Провайдеры/модели/секреты не трогать. Нет автоматического <all_urls>. Сопряжение и разрешение сайта могут потребовать явного действия пользователя в Chrome; не имитировать пользовательское согласие средствами API. Неизвестная сборка и несовпадение маркеров отклоняются без записи. Публичный status не содержит capabilities/вкладок. Обновление приложения потребует повторной валидации адаптера.
